# Notch

Фоновый агент для macOS: панель у верхнего края экрана, вокруг нотча.
Раскрывается по наведению, внутри — модули: музыка, буфер обмена, полка,
заготовки, заметка, календарь, таймеры, перевод, батарея и нагрузка
системы.

Требуется macOS 15 и новее. Apple Silicon и Intel — сборка идёт под ту
машину, на которой собирают.

## Сборка

Для разработки хватает голого бинарника:

```bash
swift build && ./.build/debug/Notch
```

Системные разрешения (Календарь, Автоматизация) работают только из
настоящего бандла — его собирает скрипт:

```bash
./Scripts/build-app.sh && open build/Notch.app
```

Выход — через иконку в меню-баре.

## Версия

Номер лежит в файле `VERSION` в корне, в одном экземпляре. Из него
`build-app.sh` берёт `CFBundleShortVersionString`, а в интерфейсе он
показывается как `v0.2.1`. Тег релиза — тот же номер с буквой `v`
впереди; если на коммите висит тег, не совпадающий с `VERSION`, сборка
останавливается, чтобы архив и исходники не разъехались.

Рядом с версией всюду стоит штамп сборки — время и короткий хеш
коммита, со звёздочкой, если в дереве были несохранённые правки.
Номер версии между правками не меняется, а штамп меняется всегда: по
нему видно, ту ли сборку смотришь.

## Релиз

```bash
./Scripts/release.sh 0.2.1
```

Скрипт правит `VERSION`, ставит тег `v0.2.1`, собирает release-бандл и
кладёт `dist/Notch-0.2.1.zip`. Дерево при этом должно быть чистым:
иначе получится архив, к которому нет коммита. Отправить тег наружу —
отдельным шагом, скрипт этого не делает сам:

```bash
git push origin main v0.2.1
```

Архив собирается через `ditto`, а не `zip`: иначе по дороге ломается
подпись бандла и система считает приложение испорченным.

## Нотаризация

Если в связке ключей есть сертификат «Developer ID Application» и профиль
`notarytool`, `release.sh` сам вызывает `Scripts/notarize.sh`: подпись с
Hardened Runtime и правами из `Scripts/Notch.entitlements`, нотаризация,
staple и DMG в `dist/`. Такую сборку открывают двойным щелчком, без
`xattr`. Что настроить один раз — в шапке `Scripts/notarize.sh`.

## Как отдать сборку другому человеку (без нотаризации)

Приложение подписано сертификатом разработчика (или ad-hoc, если
сертификата нет) и **не нотаризовано у Apple**. Это значит, что на чужом
Маке Gatekeeper его отклонит: скачанный файл помечается карантином, и
система скажет, что приложение повреждено или что разработчик не
проверен. Это не поломка сборки — так ведёт себя любое ненотаризованное
приложение.

Поэтому вместе с архивом нужно передать и способ его открыть:

1. Распаковать `Notch-0.2.1.zip` и перенести `Notch.app` в «Программы».
2. Снять карантин:

```bash
xattr -dr com.apple.quarantine /Applications/Notch.app
```

3. Запустить. Иконки в Dock не будет — приложение живёт в меню-баре,
   панель появляется у верхнего края экрана по наведению.
4. Выдать разрешения, когда система спросит: Календарь — для ближайшей
   встречи, Автоматизация — чтобы видеть, что играет в Музыке и Spotify.
   Глобальные горячие клавиши работают без «Универсального доступа».

Без второго шага можно обойтись через «Системные настройки ›
Конфиденциальность и безопасность › Всё равно открыть», но только если
приложение подписано; с ad-hoc подписью надёжнее `xattr`.

Чтобы отдавать сборку без всей этой возни, нужен платный Apple Developer
Program: подпись Developer ID и нотаризация. Тогда приложение открывается
двойным кликом, как любое другое. Пока этого нет, раздача — только
«для своих».

### Постоянная подпись при разработке

TCC запоминает выданное разрешение по подписи, а ad-hoc подпись меняется
при каждой сборке — и «Универсальный доступ» приходится выдавать заново.
Один раз завести самоподписанный сертификат:

```bash
./Scripts/make-signing-cert.sh
```

Дальше `build-app.sh` подписывает им, и разрешение переживает пересборку.
